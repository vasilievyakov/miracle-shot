# Miracle Shot — дизайн

Дата: 2026-09-14
Статус: принят с правками совета директоров (v2); фазы 1–3 идут в реализацию; фаза 4 отложена.

## 1. Что это

Menu-bar приложение для macOS, кастомная замена CleanShot X для личного использования. Живет по хоткеям, без иконки в доке. Нативный Swift (AppKit + SwiftUI), сборка через SwiftPM, тесты через XCTest.

Сознательно вырезано: запись видео/GIF, облако и шеринг по ссылке.

Ключевые мотивы кастомной версии:
- свой визуальный стиль: пресеты фонов, шрифты, цвета аннотаций в JSON, легко добавлять агентские;
- свой воркфлоу: куда сохранять, как именовать, post-capture hook;
- AI-пресеты над скриншотом на локальных моделях (фаза 4);
- полный контроль над кодом, без подписки.

## 2. Фазы

### Фаза 1 — ядро захвата
Первая рабочая веха внутри фазы: **хоткей -> область -> буфер обмена**, без лупы, истории и превью. С этого момента приложением можно пользоваться, остальное достраивается поверх.

- Хоткеи: область, окно, весь экран. Настраиваются.
- Оверлей выделения: перекрестие, лупа, размеры выделения, снап к окнам под курсором, Esc отменяет, клик без движения снимает окно.
- После захвата: картинка в буфере обмена и в файле (папка и шаблон имени из настроек), запись в историю.
- Плавающее превью в углу экрана на N секунд: кнопки «редактор», «пин», «OCR», «AI» (заглушка до фазы 4), Drag&Drop миниатюры в другое окно. Без действий исчезает; наведение курсора останавливает таймер.
- История захватов в меню-баре (последние N, открыть в Finder, открыть в редакторе).
- Окно настроек: хоткеи, папка, шаблон имени, таймаут превью.

### Фаза 2 — редактор аннотаций
Первая задача фазы: иконка приложения и палитра (раздел «Материал»), затем инструменты поверх них.

- Инструменты: стрелка, прямоугольник, эллипс, линия, карандаш, текст, нумерованные шаги, размытие/пикселизация, маркер-подсветка, кроп.
- Стиль инструмента: цвет, толщина, шрифт, размер.
- Undo/Redo.
- Фоны-пресеты: цвет, градиент, картинка; паддинг, скругление углов, тень. Пресеты в JSON в Application Support, встроенные — в ресурсах Core.
- Экспорт: буфер, файл, Drag&Drop из окна редактора.

### Фаза 3 — утилиты
- Пин: картинка в плавающей панели поверх всех окон; перемещение за фон, прозрачность и масштаб с клавиатуры/колесом, закрыть по Esc или двойным кликом.
- OCR: Vision, языки ru + en, результат текстом в буфер, уведомление с первыми строками.
- Скроллинг-захват: выбрать окно, приложение скроллит его и склеивает кадры в одно длинное изображение, результат идет по обычному потоку (буфер, файл, превью).
- Условие закрытия фазы: `ImageStitcher` проходит на корпусе реальных захватов (раздел 6), а не только на синтетике.

### Фаза 4 — AI и автоматизация (отложено)
- Пресеты: имя, промпт, формат ответа (text / markdown / csv / json), куда результат (буфер / окно / файл), хоткей, провайдер.
- Встроенные: «извлечь таблицу», «перевести на русский», «перевести на английский», «alt-text».
- Провайдеры за одним протоколом `AIProvider`:
  - `OllamaProvider` — по умолчанию. Локальная модель с vision (`qwen3.8:27b` через `localhost:11434/api/chat`, картинка в `images`). Бесплатно, офлайн, ничего не покидает машину, подтверждение не нужно. Замер на M4 Max: около 6 с на прогретой модели.
  - `ClaudeCodeProvider` — `claude -p <prompt> --output-format json` с путем к файлу; Claude читает картинку сам. Идет в лимиты подписки claude.ai, без отдельной тарификации. Скриншот покидает машину, поэтому перед отправкой показывается подтверждение с превью того, что уйдет.
  - Прямой Anthropic API с ключом не используется.
- Post-capture hook: shell-скрипт с путем к файлу в аргументе.

## 3. Архитектура

Один SwiftPM-пакет `MiracleShot`, два таргета и два тестовых таргета.

```
MiracleShot/
  Package.swift
  Sources/
    MiracleShotCore/        библиотека, Foundation + CoreGraphics + CoreImage, без AppKit
      Resources/presets/    встроенные пресеты фонов (JSON), объявлены в Package.swift один раз
    MiracleShotApp/         executable, AppKit + SwiftUI
  Tests/
    MiracleShotCoreTests/   XCTest, чистая логика
    MiracleShotAppTests/    XCTest, координатор и сервисы через протоколы и fakes
    Fixtures/scroll/        корпус реальных скроллинг-захватов для ImageStitcher
  scripts/
    build-app.sh            сборка "Miracle Shot.app"
  docs/plans/
```

Правило зависимостей: `MiracleShotApp` -> `MiracleShotCore`, никогда наоборот. В Core нет ни одного `import AppKit`.

Минимальная macOS: 14 (нужен `SCScreenshotManager`). Swift 6, strict concurrency: сервисы App-слоя — `@MainActor` классы или акторы. `CGImage` в SDK macOS 26 уже `Sendable` (проверено компиляцией с `-strict-concurrency=complete`), обертки не нужны; `Capture` и `Document` — `Sendable` value types.

Принцип: все, что является чистой функцией, живет в Core и покрыто тестами, даже если используется только одним UI-компонентом. App-слой — тонкие обертки над системными API за протоколами.

### 3.1 MiracleShotCore

Модели и логика захвата:
- `Capture` — `CGImage`, `timestamp`, `sourceAppBundleID?`, `sourceWindowTitle?`, `bounds`, `scaleFactor`.
- `CaptureState` — enum состояний: `idle`, `selecting(mode)`, `capturing`, `previewing(capture)`. Переходы — чистая функция `reduce(state, event) -> state`. Инварианты: нельзя начать второй захват во время первого; Esc из `selecting` ведет в `idle`.
- `NamingTemplate` — парсит `{date}`, `{time}`, `{app}`, `{seq}`, отдает имя файла. Безопасная замена символов.
- `SelectionGeometry` — чистая геометрия оверлея: окно под точкой из списка `WindowInfo` (rect, слой, владелец), снап рамки к границам окна с порогом, rect лупы, нормализация выделения при перетаскивании в любую сторону, пересчет между экранами с разным `scaleFactor`.
- `PreviewTiming` — состояние таймера превью: старт, пауза при наведении, возобновление, истечение.
- `PinTransform` — клампинг прозрачности (0.2...1.0) и масштаба (0.25...4.0), шаги изменения.

Редактор:
- `Annotation` — enum с associated values: `arrow`, `rect`, `ellipse`, `line`, `freehand`, `text`, `step`, `blur`, `highlight`. У каждой `id: UUID`, `style: AnnotationStyle`.
- `AnnotationStyle` — `strokeColor`, `fillColor?`, `lineWidth`, `fontName`, `fontSize`.
- `BackgroundPreset` — `Codable`: `id`, `name`, `fill` (`solid` / `linearGradient` / `image`), `padding`, `cornerRadius`, `shadow`.
- `Document` — `source: CGImage`, `annotations: [Annotation]`, `background: BackgroundPreset?`, `cropRect: CGRect?`.
- `AnnotationRenderer` — `render(_ document: Document) -> CGImage`. Один путь для превью и экспорта. Blur/pixelate через CoreImage.
- `UndoStack<T>` — массив снимков, `push`, `undo`, `redo`, ограничение глубины.

Скроллинг и OCR:
- `FrameDiff` — нормированная разница двух кадров (0...1) по сетке сэмплов; используется и для «скролл успокоился», и для «страница долистана».
- `ImageStitcher` — `stitch(frames: [CGImage]) -> CGImage`. Ищет перекрытие соседних кадров сравнением строк пикселей с допуском; статичные области (шапка, футер, скроллбар) определяются как строки, одинаковые во всех кадрах, и исключаются из поиска перекрытия. Если перекрытие не найдено — конкатенация с флагом `warning`.
- `OCRResult` / `TextBlock` — текст + rect; маппинг из Vision-наблюдений — чистая функция в Core, покрыта тестом.

Хранилище:
- `HistoryIndex` — `Codable` список записей (путь, дата, размер, источник), ограничение N, чтение/запись в JSON.
- `Settings` — `Codable`: хоткеи, папка, шаблон имени, таймаут превью, список пресетов. JSON в `~/Library/Application Support/Miracle Shot/`.

### 3.2 MiracleShotApp

Протоколы системных сервисов (объявлены в App, реализованы там же; fakes — в `MiracleShotAppTests`):
- `CaptureServicing` — `capture(rect:display:)`, `capture(window:)`, `capture(display:)`, `hasPermission`.
- `WindowListProviding` — список `WindowInfo` под курсором; реализация через `CGWindowListCopyWindowInfo` (синхронный, дешевый, годится на каждое движение мыши). `SCShareableContent` используется только для самого захвата.
- `ClipboardServicing`, `FileSaving`, `OCRServicing`, `ScrollEventSending`, `NotificationPosting`.

Компоненты:
- `AppDelegate` / `MenuBarController` — `NSStatusItem`, меню: захваты, история, настройки, выход. `LSUIElement = true`.
- `HotkeyManager` — Carbon `RegisterEventHotKey`, без Accessibility. Маппинг хоткей -> действие — чистая таблица, тестируется.
- `CaptureCoordinator` — единственный владелец `CaptureState`; принимает события от хоткеев, оверлея, превью; вызывает сервисы только через протоколы. Все error-path раздела 5 покрыты тестами с fakes.
- `CaptureService` — ScreenCaptureKit: `SCShareableContent` для окон/экранов при захвате, `SCScreenshotManager.captureImage` для снимка. Требует разрешение Screen Recording.
- `SelectionOverlay` — borderless `NSPanel` уровня `.screenSaver` на каждый экран; только отрисовка и ввод, вся геометрия — `SelectionGeometry`.
- `QuickPreviewPanel` — плавающая `NSPanel` в правом нижнем углу; миниатюра, кнопки, `PreviewTiming`, `NSDraggingSource` для Drag&Drop файла.
- `EditorWindow` — `NSWindow` с SwiftUI `Canvas`; тулбар инструментов и стилей; хранит `Document`, рендер превью и экспорт через `AnnotationRenderer`.
- `PinPanel` — плавающая `NSPanel` с картинкой, `isMovableByWindowBackground`, `PinTransform`.
- `OCRService` — обертка над Vision `VNRecognizeTextRequest`, `recognitionLanguages = ["ru", "en"]`.
- `ScrollCaptureService` — выбирает окно, шлет `CGEvent` scroll, снимает кадры через `CaptureServicing`, ждет успокоения по `FrameDiff`, отдает `ImageStitcher`.
- `SettingsWindow` — SwiftUI-форма над `Settings`.
- `HistoryMenu` — подменю из `HistoryIndex`.

### 3.3 Сборка и распространение

`scripts/build-app.sh`:
1. `swift build -c release`;
2. собирает `build/Miracle Shot.app/Contents/{MacOS,Resources}`;
3. пишет `Info.plist`: `CFBundleIdentifier = agency.blackbloom.miracleshot`, `LSUIElement = true`, `NSScreenCaptureUsageDescription`, `CFBundleIconFile`;
4. `codesign --force --sign - --identifier agency.blackbloom.miracleshot` — стабильный ad-hoc identifier, чтобы разрешение Screen Recording не слетало при каждой пересборке;
5. опционально копирует в `/Applications`.

## 4. Материал

Полстраницы про ощущение, чтобы «свой визуальный стиль» был свойством, а не лозунгом.

- Палитра: нейтральная — почти черный и почти белый для chrome, один акцент для рамки выделения, активного инструмента и нумерованных шагов. Конкретные значения фиксируются первой задачей фазы 2 вместе с иконкой; пресеты фонов — отдельная сущность и на chrome не влияют. Открытый вопрос: акцент агентский (Black Bloom) или нейтральный.
- Движение: одна кривая по умолчанию — ease-out, 180 мс. Превью появляется fade + сдвиг на 8 pt снизу, исчезает fade 120 мс. Наведение на превью останавливает таймер, уход — возобновляет. Оверлей выделения появляется мгновенно: любая задержка после хоткея читается как тормоз.
- Оверлей: затемнение черным с alpha 0.35, рамка выделения 1 pt акцентом, размеры в подписи рядом с курсором, лупа 120 pt с сеткой пикселей и без сглаживания.
- Пин: тень как у стандартного окна, без chrome; при изменении прозрачности или масштаба на 600 мс показывается HUD со значением.
- Звук: тишина. Захват — рефлекторное действие, обратная связь визуальная (превью). Решение осознанное.
- Типографика: системная SF, без кастомных шрифтов в chrome; кастомные шрифты — только внутри аннотаций по выбору пользователя.

## 5. Потоки данных

### 5.1 Захват области

```
хоткей -> HotkeyManager -> CaptureCoordinator.begin(.area)
  -> SelectionOverlay.show() -> пользователь тянет рамку -> rect + display
  -> CaptureServicing.capture(rect, display) -> CGImage
  -> Capture(...)
  -> параллельно: ClipboardServicing.copy, FileSaving.save(NamingTemplate), HistoryIndex.append
  -> QuickPreviewPanel.show(capture)
```

Захват окна: тот же поток, но оверлей подсвечивает окно под курсором (`WindowListProviding` + `SelectionGeometry`) и по клику отдает его. Весь экран: оверлей пропускается.

### 5.2 Из превью
- Редактор: `EditorWindow.open(Document(source: capture.image))`.
- Пин: `PinPanel.show(capture.image)`.
- OCR: `OCRServicing.recognize(capture.image)` -> буфер + уведомление.
- Drag: файл из истории как `NSDraggingItem`.

### 5.3 Редактор
`Document` -> пользователь добавляет `Annotation` -> `UndoStack.push` -> `AnnotationRenderer.render` для превью -> экспорт тем же рендером.

### 5.4 Скроллинг-захват
Окно -> кадр 0 -> scroll на высоту окна минус перекрытие -> ждать, пока `FrameDiff` двух последовательных снимков не упадет ниже порога (максимум 300 мс) -> кадр 1 -> ... Остановка: `FrameDiff(кадр n, кадр n-1)` ниже порога «страница не сдвинулась», либо лимит 50 кадров / 30 секунд. -> `ImageStitcher.stitch` -> обычный поток захвата.

## 6. Обработка ошибок

- Нет разрешения Screen Recording: показать алерт с кнопкой «Открыть настройки», не падать. Проверка при старте и перед каждым захватом.
- Захват вернул nil: уведомление, состояние обратно в `idle`.
- Папка сохранения недоступна: fallback в `~/Pictures/Miracle Shot/`, уведомление.
- OCR не нашел текст: уведомление «Текст не найден», буфер не трогаем.
- Скроллинг-захват: лимит 50 кадров и 30 секунд; если перекрытие не найдено — конкатенация с предупреждением.
- Ошибка чтения `Settings` или `HistoryIndex` JSON: логировать, продолжить с дефолтами, битый файл переименовать в `.broken`.

Каждый пункт — тест в `MiracleShotAppTests` через fakes сервисов.

## 7. Тестирование

- Core: XCTest через `swift test`. TDD: тест первым, затем минимальная реализация.
  - `CaptureStateTests` — все переходы и инварианты.
  - `NamingTemplateTests` — подстановки, экранирование, последовательность.
  - `SelectionGeometryTests` — окно под точкой с перекрытиями, снап у порога и за ним, лупа у края экрана, выделение «назад».
  - `PreviewTimingTests`, `PinTransformTests`.
  - `AnnotationRendererTests` — рендер документа известного размера, проверка пикселей в контрольных точках **с допуском** (по каналу, не побайтово); паддинг и скругление фона; blur проверяется как падение дисперсии в области, а не как точные байты.
  - `UndoStackTests`.
  - `FrameDiffTests` — идентичные кадры дают 0, сдвиг дает рост, шум ниже порога.
  - `ImageStitcherTests` — два уровня: синтетика (длинное изображение режется на перекрывающиеся кадры, склеивается, сравнивается с оригиналом; случай статичной шапки и футера) и **корпус реальных захватов** `Tests/Fixtures/scroll/<app>/` (кадры + ожидаемый результат), снятых вручную из Safari, VS Code, Finder, Terminal, Notion. Корпус собирается в начале фазы 3, прохождение — условие закрытия фазы.
  - `OCRMappingTests` — маппинг наблюдений Vision в `TextBlock`.
  - `HistoryIndexTests`, `SettingsTests` — round-trip JSON, миграция с битого файла.
  - `BackgroundPresetTests` — декодирование встроенных пресетов.
- App (`MiracleShotAppTests`): `CaptureCoordinator` с fakes всех протоколов — порядок вызовов, каждый error-path раздела 6, невозможность двойного захвата; таблица хоткей -> действие.
- Ручной чек-лист на каждую задачу плана только для того, что нельзя проверить иначе: отрисовка оверлея на нескольких экранах, диалог разрешений, Drag&Drop. `scripts/build-app.sh` как smoke-тест; отдельный пункт — разрешение Screen Recording переживает пересборку.

## 8. Решения и почему

- Нативный Swift, а не Tauri/Electron: оверлей, пин поверх окон, глобальные хоткеи, ScreenCaptureKit и Vision — все системное, обертки для веб-стека дороже самой фичи.
- SwiftPM без .xcodeproj: собираемость из терминала субагентами, никаких GUI-шагов. Xcode нужен только ради XCTest и SDK.
- Carbon hotkeys вместо CGEventTap: не требует Accessibility-разрешения.
- `CGWindowListCopyWindowInfo` для окна под курсором, `SCShareableContent` только для захвата: первый синхронный и дешевый, второй асинхронный и тяжелый для вызова на каждое движение мыши.
- Один рендерер для экрана и экспорта: WYSIWYG и тестируемость.
- Undo как снимки массива аннотаций: аннотаций мало, снимки дешевы, код тривиален.
- Пресеты фонов в JSON: «свой визуальный стиль» без пересборки.
- Чистая логика App-слоя вынесена в Core, сервисы за протоколами: иначе самая активная часть системы остается без автотестов, а TDD с субагентами вырождается в ручное QA.
- Локальная модель по умолчанию для AI: бесплатно, приватно, уже стоит на машине; `claude -p` — без отдельной тарификации; API с ключом не нужен.
- Тишина вместо звука захвата: обратная связь визуальная, инструмент не должен быть слышен.

## 9. Процесс разработки

- План через superpowers writing-plans; исполнение — subagent-driven-development, субагенты на Sonnet, TDD.
- Порядок задач топологический: листовые типы Core (`Annotation`, `AnnotationStyle`, `BackgroundPreset`) раньше составных (`Document`, `AnnotationRenderer`); протоколы сервисов раньше `CaptureCoordinator`.
- Каждый субагент работает в своем git worktree: общий `.build` при параллельных `swift test` дает фантомные красные тесты.
- `Package.swift` — единственная общая точка конфликта; таргеты и ресурсы (`Resources/presets`) объявляются одной задачей в самом начале, дальше манифест не трогается.
- Первая веха фазы 1 (хоткей -> область -> буфер) собирается и запускается на реальной машине до того, как стартуют параллельные задачи по оверлею и превью.

## 10. Открытые вопросы

- Акцентный цвет: агентский или нейтральный — решить первой задачей фазы 2.
